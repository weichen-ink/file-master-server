# Review 核验与修复记录（2026-11-10）

本轮以实际工作树、提交代码和可重复测试为准，核验外部 review 的五项意见。服务器和插件分别修改；不变更版本号，不打 tag。本记录不代表已完成真实桌面或移动端 Obsidian 验证。

## 1. 未提交的上传复制回退：确认是正确性问题

`asset-files.js` 中未提交的回退把暂存文件复制到最终公开名称。即使使用独占创建标志，也只能保证名称不存在，不能保证复制结束前读取不到半个文件。失败清理还可能删除已经被其他路径观察到的目标。

已仅恢复该文件到原先已提交的安全实现，保留其他文件。上传仍通过同目录独占硬链接发布完整 inode，名称冲突不覆盖已有文件，不支持时返回 501。现有原子上传、哈希去重和失败保留测试通过。恢复未提交内容本身不会产生新的提交 diff。

## 2. 首次上传才发现不兼容存储：确认是部署反馈缺陷

新增 `src/modules/image-host/storage-health.js`：启动时在实际 `storage/raw/` 卷内建立随机私有目录，验证硬链接建立与目标存在时的排他性，然后清理探测文件。错误包含权限、能力和清理失败；写入服务日志，并通过已登录的 `/api/platform/status` 返回健康状态。资产页在上传前显示中英文提示。

这只是启动时的能力快照，不能保证后续挂载、权限或容量不变。实际上传仍检查每次发布。没有按 Docker、SMB、NFS 或 exFAT 名称武断判断能力；以实际目录、文件系统和权限为准。

未采用“先检查目标不存在再 rename”的回退：检查与写入之间存在窗口，安全性取决于所有写入者都遵守同一内存队列。保留一个原子发布策略更便于维护，也不削弱已有保证。

## 3. 插件大量转发包装：确认是维护问题，不是安全漏洞

插件 `src/plugin.js` 原有 79 个无参数签名的转发方法。本轮移除 60 个内部包装；命令、菜单、向导和设置页直接导入操作函数。保留 19 个带明确签名的生命周期与稳定操作边界（另有原本的设置读写方法），便于宿主调用、网络替换及真实产物测试。

没有重新引入多层继承、mixin、动态方法安装或新的依赖注入框架。小工具函数只接收所需的设置或 app，弹窗开启函数只接收弹窗，纯引用索引和查询不再接收整个插件。复杂的宿主操作仍显式接收插件上下文；不声称所有模块已经完全解耦。

原有数据保护测试继续覆盖上传时笔记编辑、取消后的收尾、重试清单、删除前校验、下载哈希及 Excalidraw 链接。补充设置入口、向导参数、日志加载和最终 bundle 启动/剪贴板入口测试，替换依赖旧包装方法的菜单断言。

## 4. 依赖安装前删除恢复标记：确认是可恢复性缺陷

问题不能只靠后移删除标记解决：安装失败后再次更新同一提交，新旧依赖文件哈希相同，旧逻辑会跳过 npm。重启恢复也可能清除状态，或反复覆盖恢复后用户的新修改。

本轮复用原有 pending 文件，以原子替换方式保存两个状态：用户配置与水印是否恢复完成、依赖安装是否仍待完成。兼容旧版纯文本标记。

- Git reset 前先持久记录可能需要安装，覆盖 reset 后进程立即退出的窗口。
- 安装失败或不确定时保留标记和配置备份，通过更新状态接口与后台提示。
- 下次更新即使目标提交和文件哈希相同，仍重试未完成的安装。
- 启动恢复只恢复未完成的用户文件，不运行 npm，不反复覆盖已经恢复的文件。
- 无法恢复原有备份时阻止下一次更新覆盖证据；全部步骤成功后才清理。

更新恢复仍不承诺对源代码、依赖和用户数据做整体事务回滚。已损坏到不能启动的依赖环境，仍需部署者手工排除安装错误；此时网页入口也可能不可用。
